Agent 2 — analysis_agent

Il reçoit le résultat de l'Agent 1 :

Ticket Jira
     ↓
Analysis Agent
     ↓
Analyse technique

Par exemple :

Problem:
Le bouton Modifier ne permet pas d'ouvrir le formulaire.


Affected areas:
- Angular user component
- User service
- PUT endpoint


Required behavior:
- Clicking Edit opens the form
- Existing user data must be loaded
- PUT request must update the user

Il ne génère pas encore le prompt OpenCode.

Agent 3 — prompt_agent

Il reçoit :

Ticket Jira
+
Analyse technique

et produit :

CODING INSTRUCTION

Exemple :

Inspect the existing Angular project.


Implement the user edit functionality.


1. Find the existing user component.
2. Add the Edit action.
3. Load the selected user's data.
4. Open the existing edit form.
5. Connect the form to the existing PUT endpoint.
6. Preserve the existing architecture.
7. Modify only necessary files.
8. Run the relevant tests.
9. Verify the functionality.

C'est cet agent qui remplace ton generate_coding_instruction() actuel.

Agent 4 — opencode_agent

Il reçoit uniquement :

CODING INSTRUCTION

Puis :

Prompt
 ↓
OpenCode CLI
 ↓
Project
 ↓
modifications

C'est le seul agent qui possède le droit de modifier ton projet.

           1. Mode Orchestrateur

Un seul workflow qui enchaîne automatiquement les agents 1 → 2 → 3.

│              🤖 ORCHESTRATOR                 │

             ┌─────────────┐
             │   Agent 2   │
             │   Analysis  │
             └──────┬──────┘
                    ▼
             ┌─────────────┐
             │   Agent 3   │
             │    Prompt   │
             └──────┬──────┘
                    ▼
          ┌─────────────────────┐
          │ 📝 Generated Prompt │
          └──────────┬──────────┘
                     │

             ▼                │
